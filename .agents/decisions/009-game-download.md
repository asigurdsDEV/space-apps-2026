## Decision

Aiden requests Download → genuine progress → Continue before first-person gameplay. Emit a relative-path `game-assets.json` at build time containing `{ version, files }`, using the existing PWA cache version and the complete built/public asset inventory. Download/verify those static files, reuse cached responses, prepare the room/launch/cutscene modules, then enable Continue. Keep Classic/no-WebGL fallback available as before.

Most spacecraft models are generated by code, so downloading GLBs alone is insufficient. Include the generated chunks, maps, data, CSS and public props. Progress counts complete file responses plus a final preparation step, not guessed byte transfer or a timer. Failure keeps Continue disabled; retry reuses completed files.

## Why

Cold hosted downloads differ from localhost. Explicit preparation moves those transfers before play and explains the wait. It cannot guarantee GPU frame time on every laptop. Existing automatic service-worker installation remains compatible; the gate verifies/reuses its cache rather than assuming installation succeeded.

Only build-listed static URLs use cache-first with `ignoreVary`, because preview/CDN `Vary: Origin` can otherwise prevent cached module imports. Navigation and the manifest remain network-first with offline fallback. Unlisted API endpoints, including `/api/ice`, stay on the network.

## Options we didn't pick

No native installer, new game engine, fake loading timer, duplicate model files, or API/credential caching. No change to sim state, commands, scoring or multiplayer authority.

## What this changes

PWA packaging emits the manifest; app startup validates and consumes it. This is a deployment interface, outside core v0.1 sim/net contracts. Model/scene owners keep their folders. Astra reviewed the screenshot geometry; Codex owns the gate, fullscreen shell, contextual help and interior title/choice placement.
